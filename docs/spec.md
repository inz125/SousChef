# SousChef 仕様書

インタビュー形式で順次決定した仕様を記録する。決定には ID（D-xx）を振る。
変更する場合は行を消さず「~~旧決定~~ → 新決定（変更日・理由）」の形で残す。

## 1. 前提・利用者

- 利用者: 夫婦2人（1世帯のみ。複数世帯対応は当面不要）
- 利用形態: iPhone の PWA（ホーム画面に追加して使用）
- UI 言語: 日本語

### 6.2 期限の通知（D-84・D-85）

**受け入れ条件**

期限の通知（D-84）

- Given 今日が 2026-11-21、在庫に期限が 11/21 の鶏もも肉・11/22 の鮭・11/23 の牛乳・11/24 のしめじ・11/20 の豆腐・11/17 の納豆がある / When 16 時の通知を送る / Then 見出し「期限が近い食材があります」、本文「期限切れ: 豆腐」「期限が近い: 鶏もも肉、鮭、牛乳」が届く。しめじ（3 日後）と納豆（4 日前に過ぎた）は入らない

- Given 対象の食材が 8 つ（期限切れ 2 つ・期限が近い 6 つ） / When 通知を送る / Then 「期限切れ: A、B」「期限が近い: C、D、E ほか 3 つ」
- Given 期限が 0〜2 日後・1〜3 日前に過ぎた食材が 1 つもない / When 16 時になる / Then 通知は送らない
- Given 目安の期限が明日の食材 / When 通知を送る / Then その食材も入る
- Given 通知が届いた / When タップする / Then SousChef の在庫画面が開く。すでに開いていたら、それが前に出て在庫画面に移る
- Given 夫の iPhone だけがオン / When 通知を送る / Then 夫の iPhone にだけ届き、妻の iPhone には届かない
- Given オンにしていた端末で SousChef を消した（受け取りが無効） / When 通知を送る / Then その端末の登録が消え、ほかの端末には届く

通知の受け取り設定（D-85）

- Given ホーム画面に追加した SousChef / When 設定画面を開く / Then 「期限の通知」の欄に「この iPhone で受け取る」があり、オフになっている
- Given オフ / When オンにして、iPhone の通知の許可で「許可」を選ぶ / Then オンになり、この端末が受け取りに登録される。開き直してもオンのまま
- Given オフ / When オンにして「許可しない」を選ぶ / Then オフのままで「通知が許可されていません。iPhone の設定 > 通知 > SousChef で許可してください」と出る
- Given オン / When オフにする / Then 受け取りが取り消され、この端末には届かなくなる
- Given ホーム画面に追加していない Safari / When 設定画面を開く / Then 切り替えは押せず「ホーム画面に追加した SousChef で使えます」と出る
- Given オフライン / When 設定画面を開く / Then 切り替えは押せない
- Given オンの端末 / When ログアウトする / Then この端末の受け取りも取り消される

**実装の注意点**

- 対象の食材と文面を決める処理（日付の範囲・同じ名前・並び順・5 つまでと「ほか N つ」）は純粋関数にし、境界（今日・2 日後・3 日後・1 日前・3 日前・4 日前、名前が 5 つ・6 つ）を単体テストする。画面の帯（D-76 の `expiringSoonNames`）と同じ並び順にする。日付は日本時間の今日で決める（`TZ=Asia/Tokyo` の単体テスト）
- 受け取りの登録は新しいテーブル（例: `push_subscriptions`。`endpoint` 一意・鍵・登録したメンバーのメールアドレス・作成日時）に置く。許可リストのメンバーだけが自分の登録を足し・消しできる RLS にし、統合テストで「許可リスト外・未ログインは読み書きできない」を確かめる
- 送る処理は Edge Function（例: `notify-expiring`）にする。毎日 16 時（日本時間。UTC では 7 時）に Supabase の `pg_cron` と `pg_net` で呼ぶ。呼び出しは秘密の値をヘッダーで確かめ、ほかからは動かせないようにする
- Web Push は VAPID の鍵で署名する。公開鍵は画面のビルドに（`VITE_VAPID_PUBLIC_KEY`）、秘密鍵は Edge Function の秘密の設定に置く。送り先が 404・410 を返したらその登録を消す
- テストで本物の通知サービス（Apple・Google）に送らない。統合テストは手元のモックの送り先（`mockClaude` と同じように）で、送った中身と、410 で登録が消えることを確かめる
- 画面の Service Worker は vite-plugin-pwa の generateSW を使っている。`push`（通知を出す）と `notificationclick`（在庫画面を開く・前に出す）は、Workbox の `importScripts` で読む別のファイルに書く（generateSW のまま足せる）
- 通知の許可・受け取りの登録は、ほかの外部との境界と同じくインターフェース（例: `PushApi`）で切り、設定画面は Fake でコンポーネントテストする。Playwright の Chromium では本物の受け取りの登録ができないので、E2E は設定画面の表示（受け取れない環境での案内）までにする
- `docs/deploy.md` に、VAPID の鍵の作り方と登録先（Supabase の秘密の設定、GitHub の `VITE_VAPID_PUBLIC_KEY`）、`pg_cron` で呼ぶ設定の確かめ方を書き足す。iPhone は iOS 16.4 以降で、ホーム画面に追加した SousChef だけが通知を受け取れることも書く
