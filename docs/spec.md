# SousChef 仕様書

インタビュー形式で順次決定した仕様を記録する。決定には ID（D-xx）を振る。
変更する場合は行を消さず「~~旧決定~~ → 新決定（変更日・理由）」の形で残す。

## 1. 前提・利用者

- 利用者: 夫婦2人（1世帯のみ。複数世帯対応は当面不要）
- 利用形態: iPhone の PWA（ホーム画面に追加して使用）
- UI 言語: 日本語

### 2.3 在庫管理

| ID   | 項目            | 決定                                                                                                                                                                                                                                                                        |
| ---- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-06 | 登録方法（MVP） | 手入力（過去の登録からの候補補完つき）＋ レシート撮影 → AI で一括登録（確認画面で修正してから確定）                                                                                                                                                                         |
| D-09 | 数量            | ざっくり 3 段階: ある / 少ない / ない（「ない」にした食材は在庫から外れ、補完候補として残る）                                                                                                                                                                               |
| D-10 | 保存場所        | 冷蔵・冷凍・野菜室・食品庫 の固定 4 区分                                                                                                                                                                                                                                    |
| D-11 | 期限            | 任意入力。未入力なら食材カテゴリ × 保存場所から目安期限を自動推定（ユーザーが修正可、推定値であることを表示）                                                                                                                                                               |
| D-18 | 期限通知        | MVP はアプリ内表示のみ（ホームに「期限が近い食材」）。Web Push は MVP 後に検討                                                                                                                                                                                              |
| D-23 | 食材カテゴリ    | 12 分類: 肉 / 魚介 / 卵 / 乳製品 / 豆腐・大豆製品 / 葉野菜 / 根菜・いも / きのこ / 果物 / 加工品 / 主食 / 調味料・乾物（実装: `src/domain/food.ts`）                                                                                                                        |
| D-24 | 目安期限        | カテゴリ × 保存場所の日数表 ＋ 主要食材（ひき肉・刺身・もやし・鶏肉など）の個別値。個別値は同じカテゴリの食材名にキーワードが含まれる場合のみ優先（実装: `src/domain/expiry.ts`）                                                                                           |
| D-25 | 「期限が近い」  | 期限切れ = 赤、今日〜2 日後 = 黄色                                                                                                                                                                                                                                          |
| D-26 | 在庫一覧        | 上部に「すべて / 冷蔵 / 冷凍 / 野菜室 / 食品庫」の切替。期限が近い順（期限なしは最後、同じなら名前順）。期限切れは赤、2 日以内は黄色の帯                                                                                                                                    |
| D-27 | 食材の追加      | 名前を入力すると過去の登録（補完候補）からカテゴリ・場所を自動で入れる。初めての食材はカテゴリを選ぶ。保存場所の初期値は選択中のタブ。期限は目安を自動で入れ、手で変えたら目安ではなくなる。補完候補は在庫から削除しても残る                                                |
| D-28 | 一覧での操作    | 量ボタンで「ある ⇔ 少ない」を切替。「なくなった」で削除し、5 秒間「元に戻す」を表示。行タップで詳細編集（D-29）                                                                                                                                                             |
| D-29 | 詳細編集        | 名前・カテゴリ・場所・量・期限を編集でき、削除もできる。期限が目安のときだけ、場所かカテゴリを変えると今日から再推定する。手入力の期限は変えない                                                                                                                            |
| D-30 | 同期と通知      | もう一人の変更はリアルタイムに一覧へ反映し、「はなさんが 牛乳 を追加しました」のように 4 秒間通知する（自分の操作は通知しない）。変更履歴はサーバのトリガーが `inventory_events` に記録する。表示名は `allowed_members.display_name`（未設定ならメールアドレスの @ より前） |
| D-31 | 前面復帰        | アプリが前面に戻ったら「今日」と在庫を読み直す（開いたまま日付が変わる・バックグラウンド中に接続が切れる対策）                                                                                                                                                              |

| D-35 | レシピ          | 2 人前・分量つき・手順 5〜8 行。材料に「在庫あり / 買い足し / 常備」の印。主菜と副菜を並行して作る段取りのコツを添える                                                                                                                                                               |

### 2.5 レシピ・調理

| ID   | 項目             | 決定                                                                                                                                                                                                                                                                                                                    |
| ---- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-14 | レシピ保存       | 気に入ったレシピを ★ で保存。保存レシピも提案候補に含める。調理履歴を記録                                                                                                                                                                                                                                               |
| D-12 | 調理後の在庫     | 「作った」で使用食材のチェックリストを表示 → 食材ごとに「使い切った / 少ない / まだある」を選んで一括更新                                                                                                                                                                                                               |
| D-36 | ★保存            | 料理（主菜・副菜）ごとに★で保存。同じ名前の料理は 1 つとして扱い、保存し直すとレシピを最新にする                                                                                                                                                                                                                        |
| D-37 | 「作った」の詳細 | レシピから「作った」→ 材料のうち在庫にある食材ごとに「使い切った / 少ない / まだある」を選ぶ（初期値: まだある）。買い足した食材は「余った」をチェックしたものを「少ない」で在庫に追加（カテゴリは提案時に AI が付け、保存場所は補完候補→カテゴリの順で決め、期限は目安を推定）。確定で在庫を一括更新し、調理履歴に記録 |
| D-38 | 重複回避         | 直近 7 日間（日本時間）に作った料理は提案で避ける。★保存した料理は、条件に合えば候補に含めるよう AI に伝える                                                                                                                                                                                                            |
| D-39 | レシピタブ       | 下部タブ「レシピ」に★保存した料理の一覧（タップでレシピ、そこから「作った」も可）と調理履歴（日付ごと）を表示                                                                                                                                                                                                           |

### 2.7 本番環境

公開の手順は `docs/deploy.md`。main への反映で GitHub Actions が DB のマイグレーション・Edge Function・画面（Cloudflare Pages）を自動で公開する。

アクセス制御は二重にしている: ① サインアップ無効 ② すべてのテーブルの RLS で `allowed_members` に載っているメールアドレスか確認
