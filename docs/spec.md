# SousChef 仕様書

インタビュー形式で順次決定した仕様を記録する。決定には ID（D-xx）を振る。
変更する場合は行を消さず「~~旧決定~~ → 新決定（変更日・理由）」の形で残す。

## 1. 前提・利用者

- 利用者: 夫婦2人（1世帯）
- 利用形態: iPhone の PWA（ホーム画面に追加して使用）
- UI 言語: 日本語

## 2. 決定事項

### 2.1 アーキテクチャ

| ID   | 項目           | 決定                                                                                                                            |
| ---- | -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | データ共有     | クラウドでリアルタイム同期（2台の iPhone で同じ在庫を共有）                                                                     |
| D-02 | 提案の頭脳     | 生成 AI（Claude API）                                                                                                           |
| D-04 | フロントエンド | React + TypeScript + Vite（vite-plugin-pwa）                                                                                    |
| D-05 | バックエンド   | Supabase（Postgres + RLS + Realtime + Auth + Edge Functions）。Claude API キーは Edge Function 側に秘匿し、ブラウザには置かない |
| D-08 | ホスティング   | Cloudflare Pages（PR ごとのプレビュー URL）                                                                                     |
| D-17 | オフライン     | 閲覧のみ可（最後に同期した在庫・保存レシピを表示）。編集はオンライン時のみ                                                      |

### 2.2 認証・世帯

| ID   | 項目     | 決定                                                                                                                                  |
| ---- | -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| D-15 | ログイン | メールのワンタイムコード（OTP）。iOS PWA ではマジックリンクが Safari 側で開きセッションが PWA に渡らないため、6桁コード入力方式にする |
| D-16 | 世帯     | 片方が世帯を作成し、招待コードでもう片方が参加。全データは世帯単位で RLS により分離                                                   |

### 2.3 在庫管理

| ID   | 項目            | 決定                                                                                                                                                                              |
| ---- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-06 | 登録方法（MVP） | 手入力（過去の登録からの候補補完つき）＋ レシート撮影 → AI で一括登録（確認画面で修正してから確定）                                                                               |
| D-09 | 数量            | ざっくり 3 段階: ある / 少ない / ない（「ない」にした食材は在庫から外れ、補完候補として残る）                                                                                     |
| D-10 | 保存場所        | 冷蔵・冷凍・野菜室・食品庫 の固定 4 区分                                                                                                                                          |
| D-11 | 期限            | 任意入力。未入力なら食材カテゴリ × 保存場所から目安期限を自動推定（ユーザーが修正可、推定値であることを表示）                                                                     |
| D-18 | 期限通知        | MVP はアプリ内表示のみ（ホームに「期限が近い食材」）。Web Push は MVP 後に検討                                                                                                    |
| D-23 | 食材カテゴリ    | 12 分類: 肉 / 魚介 / 卵 / 乳製品 / 豆腐・大豆製品 / 葉野菜 / 根菜・いも / きのこ / 果物 / 加工品 / 主食 / 調味料・乾物（実装: `src/domain/food.ts`）                              |
| D-24 | 目安期限        | カテゴリ × 保存場所の日数表 ＋ 主要食材（ひき肉・刺身・もやし・鶏肉など）の個別値。個別値は同じカテゴリの食材名にキーワードが含まれる場合のみ優先（実装: `src/domain/expiry.ts`） |
| D-25 | 「期限が近い」  | 期限切れ = 赤、今日〜2 日後 = 黄色                                                                                                                                                |

### 2.4 献立提案

| ID   | 項目            | 決定                                                                                                                                                |
| ---- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-03 | MVP の主眼      | 在庫から献立提案                                                                                                                                    |
| D-07 | 提案単位（MVP） | 今日の 1 食（主菜＋副菜）                                                                                                                           |
| D-19 | 候補数          | 3 案。気に入らなければ再提案                                                                                                                        |
| D-13 | 考慮条件        | ① 期限が近い食材を優先 ② 調理時間の上限（提案時に指定） ③ 夫婦それぞれの好み・苦手・アレルギー（アレルギーは絶対除外） ④ 直近の調理履歴と重複しない |
| D-20 | 不足食材        | 提案時に「在庫のみ」/「買い足し OK」を切替。買い足し OK のときは不足食材を明示                                                                      |
| D-21 | AI コスト       | 世帯あたり 1 日の回数上限（初期値: 提案 20 回 / レシート 10 回、設定で変更可）。上限判定はサーバ側                                                  |

### 2.5 レシピ・調理

| ID   | 項目         | 決定                                                                                                      |
| ---- | ------------ | --------------------------------------------------------------------------------------------------------- |
| D-14 | レシピ保存   | 気に入ったレシピを ★ で保存。保存レシピも提案候補に含める。調理履歴を記録                                 |
| D-12 | 調理後の在庫 | 「作った」で使用食材のチェックリストを表示 → 食材ごとに「使い切った / 少ない / まだある」を選んで一括更新 |

### 2.6 UI

| ID   | 項目     | 決定                                                                                      |
| ---- | -------- | ----------------------------------------------------------------------------------------- |
| D-22 | デザイン | iOS ネイティブ風、下部タブ（在庫 / 献立 / レシピ / 設定）、ダークモード対応、片手操作重視 |

## 3. MVP スコープ

1. 認証（OTP）・世帯作成・招待コード参加
2. 在庫 CRUD（手入力・補完・期限推定）とリアルタイム同期
3. 献立提案（1 食 × 3 案、条件指定）
4. レシピ表示・★保存・「作った」による在庫更新と調理履歴
5. レシート撮影による一括登録
6. 好み・苦手・アレルギー設定、AI 利用回数上限
7. PWA 化（ホーム画面追加、オフライン閲覧）

## 4. MVP 後の候補

- 数日〜1 週間の献立計画と買い物リスト
- Web Push による期限通知
- 冷蔵庫写真からの食材認識、バーコード
- 手持ちレシピ（URL・写真）の取り込み
