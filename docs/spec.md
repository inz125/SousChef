## 1. 前提・利用者

- 利用者: 夫婦2人（1世帯のみ。複数世帯対応は当面不要）
- 利用形態: iPhone の PWA（ホーム画面に追加して使用）
- UI 言語: 日本語

利用者の要望: 献立を提案するとき、ご飯が炊いてあるかどうかを確認する。

**インタビュー待ち。** 受け入れ条件はまだない。確認するタイミング（提案の前か条件の一つか）、答えの扱い（提案に反映するだけか、在庫の「主食」とどう関係させるか）は、インタビューで決める。

### 6.4 ご飯が炊いてないとき、主食をうどんやパスタなどから選ぶ（仕様未確定）

利用者の要望: ご飯が炊いていないときは、主食をうどんやパスタなどから選べるようにする。6.3 とセットで決める。

**インタビュー待ち。** 受け入れ条件はまだない。選択肢の一覧（うどん・パスタ以外に何を含めるか）、選んだ主食を献立（主菜・副菜の組み合わせ）にどう反映するか、在庫にない主食の扱いは、インタビューで決める。

### 6.5 買ってきた肉の冷凍と、解凍の勧め（D-46〜D-49）

利用者の要望: 買ってきた肉はスーパーから帰ったら冷凍し、使う前の日に冷蔵へ移して解凍する。これを在庫に反映し、解凍を促す。

#### 受け入れ条件

**肉は冷凍で登録（D-46）**

- Given 補完候補に「鶏もも肉（肉・冷蔵）」がある / When レシートから「鶏もも肉」を読み取る / Then 確認画面の保存場所の初期値は「冷凍」
- Given 冷蔵タブを選んでいる / When ＋で「豚こま肉」を入力しカテゴリ「肉」を選ぶ / Then 保存場所が「冷凍」になり、期限の目安は冷凍の日数（D-24）
- Given 手入力で肉の保存場所を「冷蔵」に変えた / When 追加する / Then 冷蔵で登録される（初期値を変えるだけで、選んだ値は尊重する）
- Given 補完候補に「サーモン（魚介・冷蔵）」がある / When 登録する / Then 冷蔵のまま（魚介は対象外）
- Given 「作った」で買い足した「豚ひき肉」の「余った」をチェック / When 確定 / Then 冷凍の「少ない」で在庫に追加される
- Given 在庫に冷凍の「鶏もも肉」と解凍中の「鶏もも肉」がある / When レシートで「鶏もも肉」を登録 / Then 冷凍の行を「ある」に戻して期限を推定し直す（解凍中の行は変えない）。冷凍の行がなければ冷凍で新しい行を作る

**解凍（D-47）**

- Given 冷凍タブに肉の「鶏もも肉（ある）」がある / When 行を左スワイプ / Then 「削除」「少ない」の隣に「解凍」ボタンが出る（肉以外・冷凍以外の行には出ない）。編集画面にも「解凍」ボタンがある
- Given 「解凍」を押した / Then 「全部」「一部」と「キャンセル」を選ぶシートが出る
- Given 「全部」を選ぶ / Then 行の保存場所が冷蔵になり、「解凍中」の印が付き、期限は今日の 2 日後（目安）になる。量は変えない
- Given 「一部」を選ぶ / Then 冷凍の行に残す量（ある / 少ない。初期値は今の量）を選んで確定すると、冷凍の行は量だけ変わり、冷蔵に同じ名前・カテゴリで量「ある」・「解凍中」・期限は今日の 2 日後（目安）の行が追加される
- Given 解凍中の行 / Then 一覧で名前の横に「解凍中」の印が出る。期限の色分け（D-25）は通常どおり（解凍した日から黄色）
- Given 解凍中の行の保存場所を編集で冷蔵以外に変える / Then 「解凍中」は外れ、期限は D-29 のとおり再推定する
- Given もう一人が解凍した / Then 一覧にリアルタイムで反映され、D-30 の通知（更新・追加）が出る
- Given オフライン / Then 「解凍」は使えない（D-17）

**解凍の勧め（D-48）**

- Given 18 時以降・冷凍に肉の行が 1 つ以上・冷蔵に解凍中の肉の行がない / When 在庫画面を開く / Then 一覧の上に「明日の肉を解凍しませんか？」の帯が出て、冷凍の肉が期限が近い順に並び、それぞれに「解凍」ボタンがある
- Given 帯の「解凍」を押す / Then D-47 と同じ「全部 / 一部」のシートが出る。解凍すると条件を満たさなくなり帯は消える
- Given 帯の「今日はいい」を押す / Then その日はその端末で帯を出さない（翌日 18 時以降はまた出る）。もう一人の端末には影響しない
- Given 18 時より前、または冷凍に肉がない、または解凍中の肉がある / Then 帯は出ない
- Given 17 時台に開いたまま 18 時を過ぎ、アプリが前面に戻った / Then D-31 の読み直しで帯の条件を判定し直す
- Given オフライン / Then 帯は出さない

**冷凍の肉の提案（D-49）**

- Given 在庫に冷凍の「鶏もも肉」と冷蔵の「豚こま肉」がある / When 献立を提案 / Then AI には在庫の冷凍・解凍中の別が伝わり、冷蔵・解凍中の肉を優先するよう指示される
- Given 冷凍の肉を使う案 / Then 手順の最初に解凍の工程があり、合計時間に解凍時間が含まれる（AI への指示で担保。テストではプロンプトに指示が入っていることを確かめる）
- Given 案の材料が在庫の冷凍の肉に当たる / Then 案の一覧とレシピの材料に「冷凍・要解凍」の印が付く
- Given 「冷凍・要解凍」の材料があるレシピを開く / Then レシピの上に「冷凍の 鶏もも肉 を使います。明日作るなら今のうちに冷蔵へ移しましょう」と「解凍」ボタンが出て、D-47 の解凍ができる。解凍すると印と案内は消える
- Given ★保存したレシピ・調理履歴からレシピを開く / Then 同じく今の在庫で印と案内を出す

#### 実装の注意点

- DB: `inventory_items` に `thawed_on date null` を足す（null = 解凍中ではない）。「解凍中」は `location = 'fridge'` かつ `thawed_on` あり。保存場所を冷蔵以外にする更新では `thawed_on` を null にする
- 期限の目安: 解凍中の行は `thawed_on + 2 日`（`src/domain/expiry.ts` の D-24 の表より優先）。D-29 の再推定やレシートの更新でも、解凍中の行はこの値を使う
- 肉の保存場所の初期値（D-46）は `src/domain` に関数を 1 つ置き、`receiptDrafts`・`renameDraft`・`ItemForm` の補完/カテゴリ選択時・`cookedChanges` の余りで使う。補完候補（`food_catalog`）に保存される場所も冷凍になる
- レシートの同名更新（`stockOf`）は、肉なら冷凍の行だけを対象にする
- 「冷凍・要解凍」の印は、AI の応答ではなく画面側で判定する: 材料の `source` が `stock` で、`stockCandidates` の先頭が「肉・冷凍」の行なら印を付ける（解凍中の行があれば期限が近いのでそちらが先頭になり、印は付かない）。今の在庫で判定するので、解凍すると消える
- AI へのプロンプト（`buildMealPrompt` の `describeItem`）に「冷凍」「解凍中」の注記を足し、条件に「冷蔵・解凍中の肉を優先」「冷凍の肉を使うときは手順の最初に解凍を入れ、その時間も合計時間に含める」を足す
- 帯の「今日はいい」は localStorage に日付で保存する（読み書きは try/catch。失敗しても帯が出るだけ）
- 時刻の判定は端末のローカル時刻（日本時間の前提、`toIsoDate` と同じ）
