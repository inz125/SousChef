# 開発プロセス

このドキュメント自体を開発対象として扱い、機能を 1 つ作るごとに振り返って更新する。

## 1. 基本サイクル（機能 1 つ分）

1. **仕様確認**: `docs/spec.md` の該当 D-xx を確認。曖昧な点はインタビューで決めて追記する
2. **受け入れ条件を書く**: ユーザー視点の振る舞いを箇条書き（Given/When/Then）
3. **TDD**: 外側から内側へ
   - E2E（Playwright, iPhone ビューポート）で受け入れ条件を 1 本 Red にする
   - ドメインロジックを単体テスト（Vitest）で Red → Green → Refactor
   - UI コンポーネントを Testing Library で Red → Green → Refactor
   - Supabase との結合（RLS・Edge Functions）を統合テストで確認
   - E2E を Green にする
4. **品質ゲート**: `npm run check`（format:check / lint / typecheck / 全テスト）を通してからコミット。CI（GitHub Actions）でも同じものと `build` を実行する
5. **振り返り（KPT）**: 下の「改善履歴」に追記し、必要ならこのドキュメント・CLAUDE.md・CI・スクリプトを更新

## 2. テスト方針

| 層             | ツール                            | 対象                                                                | 方針                                     |
| -------------- | --------------------------------- | ------------------------------------------------------------------- | ---------------------------------------- |
| 単体           | Vitest                            | ドメインロジック（期限推定、提案条件の組み立て、AI 応答の検証など） | 純粋関数として切り出し、最も厚く書く     |
| コンポーネント | Vitest + Testing Library          | 画面・部品の振る舞い                                                | ユーザー操作で検証。実装詳細に依存しない |
| 統合           | Vitest + Supabase ローカル（CLI） | RLS、Edge Functions、Realtime                                       | 世帯間のデータ分離は必ずテストする       |
| E2E            | Playwright（iPhone ビューポート） | 主要動線                                                            | 少数精鋭。AI はモックサーバで固定応答    |

- **AI（Claude API）**: 実 API はテストで呼ばない。プロンプト組み立てと応答スキーマ検証を単体テストし、Edge Function はモックで統合テスト。応答は zod 等で必ず検証してから使う
- **時刻**: 期限・日次上限などは時刻を注入可能にしてテストする

## 3. ブランチ・コミット

- 1 コミット = 1 つの意味のある変更（Red/Green/Refactor を細かく刻んでもよい）
- コミットメッセージは日本語可。先頭に種別（feat / test / fix / refactor / docs / chore / process）

## 4. 改善履歴（KPT）

### #0 プロジェクト開始（2026-10-25）

- **Keep**: 仕様をインタビュー形式で決め、決定に ID を振って `docs/spec.md` に記録した
- **Problem**: まだ実装サイクルを回していない
- **Try**: 最初の機能（プロジェクト雛形 + 期限推定ロジック）でこのサイクルを試し、手順の過不足を見直す

### #1 雛形 + 期限推定ロジック（2026-10-25）

- **Keep**: Red を毎回確認してから実装した。Refactor で自分の実装を疑ったことで「鶏ガラスープの素が鶏肉扱いになる」不具合をテスト化して直せた
- **Keep**: 日付を `YYYY-MM-DD` 文字列で扱い「今日」を引数で渡すことで、タイムゾーンや現在時刻に依存しないテストにできた
- **Problem**: フォーマッタが無く長い行が残った。CI も無く、品質ゲートが手元の実行頼みだった
- **Try（実施済み）**: Prettier を導入し `npm run check` に format:check を追加。GitHub Actions で check + build を実行
- **Try**: Refactor 段階では「別カテゴリなのに名前が一致する」のような境界ケースを意識的に 1 つ以上探す
- **Try**: E2E（Playwright）は最初の UI 機能で導入する
